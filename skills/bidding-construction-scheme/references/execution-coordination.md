# Execution coordination for paired bid deliverables

Use these scheduling and reuse rules without changing the selected format, mandatory content, evidence hierarchy, stop conditions, or delivery verification. They apply to construction, service and mixed assignments under their existing mode-specific rules.

## Shared intake and task routing

Complete the existing source inventory/hashes and inspect every required spreadsheet sheet, document, drawing, photo and archive. Keep one source register with exact row/page/drawing locations, authority, uncertainty and impact. Reuse its BOQ-to-work-package mapping and extracts across authors; a worker must still inspect the raw evidence supporting its technical conclusions. Never treat an extraction summary as proof of complete coverage.

Classify the mode, select/fingerprint the format, and establish the project contract before authoring. Read the existing references at their specified stages. Technical authors receive `authoring-and-evidence.md` and the applicable format/mode rules; schedule workers receive `schedule-and-workbook.md`; reviewers receive `verification.md`. Do not load historical example details into each worker or reuse their project facts. The coordinator reads all applicable requirements, including before-writing references.

Use separate worker draft/report files for substantial independent work. Small edits stay serial when delegation would cost more than it saves. If delegation is unavailable, perform the same tasks in dependency order with no reduction in deliverables or checks.

## Useful independent tasks

| Stage | Tasks that can run concurrently | Required merge boundary |
|---|---|---|
| Evidence after assignment of distinct source sets | BOQ work-package extraction, drawing/figure evidence, tender requirements and current standards verification | Coordinator reconciles all sources, source authority, scope, mode and format before drafting |
| Chapter 1 | Independent discipline methods from the accepted BOQ register; supporting source crops and standards evidence | Coordinator completes and reconciles Chapter 1 first, including hazards, interfaces and unknown values |
| Remaining content | Independent chapters responding to completed Chapter 1; draft schedule/resource/temporary-land data from the same work-package register | Coordinator reconciles resources, dependency logic, Word appendices and workbook data before generation |
| Final frozen revision | Read-only engineering/BOQ coverage, selected-format fidelity, paired-data and assigned visual-page reviews | Coordinator gathers all reports and resolves findings before release |

Give each worker a bounded scope, source/contract revision, assigned row/topic IDs, output path and required checks. Return substantive prose/data or review findings with source locations, covered requirements, missing evidence and dependencies. The coordinator must reconcile overlaps and omissions; a claimed chapter count is not substantive coverage.

## Single writer and ordered release

- The coordinator alone edits the canonical project contract, work-package/schedule/resource registers, builder and final DOCX/XLSX. Workers return drafts and proposed records, never competing final file edits. Template/profile selection, allowed clones, table schemas and legacy slots remain centralized and unchanged.
- Keep Chapter 1 first as required by `workflow.md`; later chapters may gather evidence earlier but cannot finalize against an unfinished method statement. Service tasks follow their tender-specific structure and corresponding coverage audit.
- Schedule and resource data may be prepared alongside independent chapter drafts once Chapter 1 is reconciled. Word and all five Excel sheets consume the same finalized IDs, dates/day indices, quantities, dependencies and milestones. Do not let workers independently choose durations or fabricate site/land/equipment data.
- Keep source crops, standard clauses and generated concepts distinct with the existing provenance and inspection requirements. Reuse extractions/renders only for matching source hash, page/crop and settings; older standard-status checks do not establish current status.
- Missing technical inputs and user-confirmed format/page-limit exceptions retain their existing stop conditions. Independent work can continue, but dependent calculations, claims and release must wait.
- Run the builder check before generation. A single owner performs final Word/WPS opening, field/TOC update, save and PDF export. Do not run simultaneous Office saves/exports or audit a file still being written.
- After final pagination, update the workbook response-index locations, then run all existing selected-profile/fidelity, protected XML, paired-output, engineering and visual checks on those final revisions. No added coordination step replaces `audit_latest_format.py`, paired validation, legacy fidelity, five-sheet renders, or service-specific coverage auditing.

## Revision and coverage control

Distribute read-only page/sheet reviews over non-overlapping ranges when useful, with explicit coverage of every PDF page and all five workbook sheets plus the required detailed samples. Collect findings by file/page/cell and source reference; workers do not repair the same document simultaneously.

When a source or canonical register changes, invalidate dependent chapters, figures, schedules, appendix values and reviews. Refresh affected work, regenerate the paired artifacts, repeat the required final checks and visual inspection against the new revision, and update page references after any pagination change. Earlier successful reports cannot certify later files. Preserve existing final-folder hygiene and do not deliver while any mandatory check is unresolved.
